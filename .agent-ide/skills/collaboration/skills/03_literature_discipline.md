This booklet is the rule set for reading literature as an agent inside this repo. It governs **behaviour, not file layout**: nothing here prescribes a directory, a schema, or a checklist to fill in. The failure it exists to prevent is the one that reads as productive — a batch of papers summarised by a script, fluent and unverifiable, going straight into a manuscript.

# 1. A question before a search

- Before searching, write down the question this paper is supposed to answer: which variable, which mechanism, which claim in the manuscript. If no such question can be stated, do not search for keywords — and if a paper arrives anyway, do not read it.
- A usable question is answerable in principle. "What does this literature say about diffusion" is not a question; "does this paper give me a control I do not have" is.
- When the question changes mid-reading, say so and stop: a paper read against a question it does not answer is time spent without a result.

# 2. One paper at a time, read by the agent

- Read the paper yourself, in this turn. Do not summarise literature by fetching many abstracts, running an extraction script over a folder, or queueing items and walking away. Batch reading produces garbage that looks like knowledge, because a fluent summary of an unread paper cannot be told apart from a real one.
- Do not outsource the judgement either: no scoring rubric, no automated verdict from metadata. The verdict is yours, and it has to be defensible in one paragraph.
- Reading order is decided after each paper, not scheduled in advance.

# 3. Three endings, and abandonment counts

Every paper ends in exactly one of these, stated plainly:

- **Usable** — name the quantity it maps to in this work and what comparison or experiment it would license.
- **Discussion only** — it supports or contests a claim in prose; say which sentence of the manuscript it touches. Do not manufacture an experiment to justify it.
- **Abandoned** — say what is missing (a variable, a condition, a reported statistic) and which alternative readings were considered and rejected.

Abandoning is a result. The rule that matters is the negative one: **never invent a probe for a paper that does not support one** — that is how a paper acquires experiments nobody asked for.

# 4. Keep evidence, not a filing system

- Write the conclusion in your own words, short. Keep the numbers you might cite with their source — table, page, cohort, definition — because every number in the manuscript must be traceable later, and memory will not do it.
- Write the sentence the manuscript may use while you still have the paper in front of you.
- Where any of this lives, and in what shape, is decided per project at the time. Do not create a directory template, a manifest, or required fields: the moment a structure exists, content gets produced to fill it.

# 5. Record your own misjudgements

- When a paper turned out to matter less than expected, or a mapping turned out to be wrong, write one line about why. These notes are worth more than any rubric, because they come from actual mistakes.
- When a search round returns nothing usable, that is also worth one line: which question it failed, so the same search is not repeated next week.

# 6. Light modes, kept in their place

- A quick card for a paper being scanned to design an experiment is fine — but it is not a deep read and must not be presented as one.
- A three-pass read is for claims that will be contested; when used, keep the passes distinct and let the third pass end in a verdict, not in more notes.
- Do not adopt a reading style from another discipline wholesale; take the part that answers this repo's question.
