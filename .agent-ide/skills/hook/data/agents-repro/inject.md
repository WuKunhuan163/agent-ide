## 1 Reproduction tests

第 1 章管的是“要不要出复现测试、怎么出”。它的起点是一条纪律：没有点单就没有案例目录——纠正定义、讨论方法、解释标准都不是委托，这类回合的产物是文字，不是 `tmp/reproduce-test/<id>/`。案例被定义成一个**小闭环**而不是一个动作：收料（读哪几处具名依据）、落稿（改哪一节）、检查、feed、产物，五样要在同一份提示里凑齐。出题的层级与执行的层级分开：被测的那一层不写案例，谁委托谁出题；用户说“上闭环”指的是我自己去做 1.8 落稿、1.9 检查、1.10 回填，不是让我转手写案例。只有在用户明确要复现测试时才出案例，其余情况自己动手。

### 1.0 五份契约

把案例的骨架定成五份契约，缺一份就不算案例。委托要逐字引用用户的话，并把每条映射到落点（条款 → 文件与章节）；边界要写清哪些路径可改、哪些一个字符都不许动；产物要给绝对路径、字面文件名与每个文件的必填字段；判据要一行一个数或一条 `grep`，并带它的 `path:line` 出处；缺口要写清缺什么、用哪条命令补、补出哪个文件。

### 1.1 七步与验收

给的是七步加验收，顺序固定。写案例前先答三问：这一节要什么、喂给谁、现在缺什么；然后定 `id` 与一句话目的；写五份契约；先量基线（字数、段数、条目数、每个目录的文件数）并放在 `CRITERIA.md` 顶部；写结果判据（数字、判据、怎么判、阈值），不许出现“高质量”“读起来顺”；写行为判据（边界、不自造键、不抄句、不写 todo、三条自检），每条都要能在交付里 `grep` 到；写一个正例与两三个反例（越界、模板句、清单体）；最后跑 `python3 tmp/reproduce-test/handoff.py <id>`，把它输出的整段落贴出来——那是下发给新复现 session 的指令，标题写 `PROMPT`（大写、独占第一行、正文在下面、内部不套围栏），因为读它的是一个没见过这轮对话的会话。所有产物路径为绝对路径且落在案例自己的 `out/` 里，工作目录与每个产物路径从接收方那里解析到同一处。

### 1.2 判据的形状

规定判据的形状：一行一条，`| id | criterion | how judged |`，`R*` 与 `B*` 连续；“怎么判”必须是命令、阈值或 `path:line`，没有就不是判据；结果判据判产物、行为判据判纪律，两张表不合并；每条判据要把“没做”与“做错”分开，例如加厚区间既罚低于下限也罚改写成另一段。

### 1.3 案例的五种病

列了案例的五种病与对治：含糊（“学术化”“适当加厚”）要用数值区间与 `grep` 计数；漏件（只写正文、忘了前置实验、没有重跑）要先读这一节在链条里的位置；没有缺口（通篇没有一条命令）要数每个目录的文件数，空的就换一次重跑；判据不可判（判据是形容词）要一条判据一条命令，跑不了就删；口头打发（三行加一句“交给执行层”）要跑 `handoff.py` 并把下发给新 session 的指令整段贴出，标题为 `PROMPT`。

### 1.4 离开前讲清喂了什么

是离开前必须讲的故事，四句话，缺一句算本轮不合格：这一节讲的是谁遇到什么问题、卡在哪、怎么打开、后面谁接（只用读者语言，不铺清单）；喂进去的是哪一句（逐字引，并说它在故事里是起因、转折还是结论）；哪个点变了、读者之前看到什么之后看到什么（各给一两句局部上下文）；这一句喂给谁（下游的节、列或数，没有下游就是孤句）。故事里出现“本章介绍”“分别阐述”这类空动词，或把改动报成“改了 N 处”而没有局部上下文，都算失败。

**5. 对着样张读一遍（口述也要点名样张）**：说出样张名（`report/samples/<set>`），指出这一节缺它哪个段落功能，并拿我们的一句与它的一句并排。复述里不出现样张名与段落功能的，按未复述计——那是“做了什么”的汇报，不是观感。
**6. 两栏不许合并**：可数特征（每节句数、每段引用数、段长）一栏，带命令；观感复述一栏，带引句。只交可数栏按未交付计；只交观感栏按未测量计。

### 1.5 出题前必读两处，判据要能读出

规定出题前必读的两处与四条硬要求。必读的是本章全文与 `.agent-ide/skills/agent-ide/SKILL.md:199-240`；读不到原话就不许写。四条硬要求是：案例由 owner 在新会话跑，我不跑、不请求跑、交付后也不追问；先写 `a_pred.md`（预测哪几条判据会失败）再下发，事后补写的叫总结不叫预测；入口第一行写工作目录、路径全为绝对、下发前跑存在性检查并贴输出、产物路径在案例目录内；每条判据都要指名它靠导出或命令输出的哪一行成立，指不出的删掉。装饰性判据一律不算判据——字数上限、词重合率、形容词、需要人手工数的量，都是把怀疑写成规则。

### 1.6 读回一份已交付的案例，并把暴露的弱点 feed 回去

**Purpose:** 跑回来的是一次导出，不是一句“这是哪个案例”。

拿到结果先做五件事，顺序不变：

1. 先 probe 再命名案例：按 probe 规则取导出（`agent-ide context --probe <文件>`、`--bindings`、`--key <key>`），把这次会话整段读完——跑了哪些命令、先打开哪几个文件、范围在哪一步飘了；读完之后才说这是哪个案例。凭用户一句话认定案例、再去对它没跑过的判据打分，是评估第一种错法。
2. 判之前先贴针的读数：`默认针` 是钩子触发的动作名，不是搜索串——不许拿它去 `grep`、不许自造探针、不先把问题放宽；针取工作目录根的 `./probe`（项目默认针）：只传路径，`agent-ide context --probe ./probe`，不 `cat`、不贴进回复；结果按 hits 再按时间排，第一行是最近那场，拿 key 去 `--key` 读全；命中 0 才算针无效，才记 unjudged；四条禁令挂在同一根针上——不翻绑定表找 key、不问“哪一场”、不换近义词重试、不把针贴进回复（针进会话会命中自己）。
3. 两栏不许合并：结果栏写“判据 — pass|fail — 导出行或命令输出”，行为栏写越界、跳步、绕开针的轨迹；只有结果没有行为，会把“只顾打分没做任务”的跑法藏起来。
4. verdict 写在下一轮会读的地方：`card.json` 的 `verdict` 与 `fed`，读数落 `tmp/compare-loop/<wish>/readings.md`；只写在回复里的评估不算评估。
5. 默认 feed：除非用户明说不要 feed，否则先定位这份案例是为了验哪几条条款、在哪份文档里，再把暴露的弱点逐条 feed 到那几条上，一行一个弱点，带 `located_by` 与 `downstream`；用户点名了位点就只 feed 那些；feed 不合用会被叫停，空着不 feed 才是没法纠正的错。

### 1.7 像老板带新人一样，先给执行层交代生态

只给契约与边界的案子，等于把人扔进车间却不告诉他有哪些机器。执行层没有见过这轮对话，它不知道有 GPU 命令行、不知道入口是哪个、不知道哪条规矩踩了要付钱。所以每份 `PROMPT` 都带一段**生态**：你是谁、你能用什么、文档在哪、哪一条硬规矩不许破。

1. 点名机器，不只点名路径。任务可能用到的每个资源——`compshare`（UCloud GPU）、`huggingface`、`kaggle`、`aliyunpan`、`overleaf`、`pdf-reader`、`arxiv`、`autodl`——给出启动器（`.agent-tools/<skill> …`）、文档（`<项目>/.agent-ide/skills/<skill>/SKILL.md`）、以及一句话用途。
2. 硬规矩要引原句，不许转述。`compshare` 的两条是：库存必须走 `CheckCompShareResourceCapacity`；回合不许留机器在 `Running`，必须以 `compshare settle <id>` 收尾。要它自己去翻的规矩，等于没有这条规矩。
3. 报预算。GPU 小时数、token、下载体积，或一句“完全没有网络”。没有预算的案子会引出一次付不起的运行。
4. 说明不可用的是哪些。“本案没有 GPU”“不联网”“不许装依赖”——沉默不会被理解成禁止，只会被理解成允许。
5. 把生态绑到委托上。需要 GPU 就写明哪个包用、预计跑多久；不需要就写明全程本机。

**评估只读：跑回来那棵树就是证据。** 不许 `git mv`、不许补它没生成的文件、不许把它留反的目录改回来、不许“顺手修一下”。缺陷写进行为栏、feed 到它违反的那一条；我一动手，“它到底是懒还是不会”就再也判不出来。评估期间若动过盘，读数里记一行，树还原成跑完时的样子，这一轮标 `contaminated`。

**提示只写契约，不写诊断。** 提示给契约位置、边界、产物与生态；不写哪里错了、错几处、哪一条受影响、要去找哪一类缺陷。计数只存在于 `CRITERIA.md` 的阈值（`必须为 0`、`必须等于 118`）与作者的 `a_pred.md` 里；提示只说文献库必须满足 `1.8-87`，发现留给 `1.9`。`python3 tmp/reproduce-test/leak-check.py <案例>/PROMPT.md` 打印 `OK` 或逐行列出泄露，只有 `OK` 才许下发。

**委托逐字引用，并由程序证明。** 用户的每条消息原样存进案例旁的 `commission.txt`，一行一条；`PROMPT` 用 `> ` 逐条重复，并写明由哪个产物、哪条判据兑现；没产物的要求还不算案子。`quote-check.py` 打印 `OK <n> quotes` 或 `MISSING`，改写过的句子在下发前改回去。
