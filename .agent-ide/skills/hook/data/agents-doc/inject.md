## 3 Editing a shared document

第 3 章管共享文档的写法，前提是这份文档会被复制到另一个项目仍然成立。

### 3.1 先凑证据

是先把证据凑齐：本体与平铺介绍是一份文本的两种形态，改一侧必须同轮改另一侧，没有“只改措辞”“意思没变”的例外，落后的一侧就是分叉；改动或删除前先指明来源（用户原话、项目记录或“无”），只有“无”才许可删除；不写用户没给的规则，确实需要就标“proposed”并说明它解决什么；改规范、定调文档或角色层之前，先找回用户关于这件事的原话，带行号与一句引文。取语境按固定顺序：先 `agent-ide context --bindings`，再 `--key <key>` 渲染；读自己的用本轮现写的 nonce 作探针，判别人的用对方写过的片段；没有有效探针就退回 `--bindings`。自检不算证据：`grep`、`wc -l`、清单只能证明做完了，不能证明做对了。写的方式是强化而不是新增：先找已经在承担这个目的的地方，让它说出新话；新建第二个文件、索引或记忆条目都是分叉。规范用陈述句写“这里放什么、按什么顺序、什么禁止”，不写“可以……也可以”。

### 3.2 写形状不写现场

是写形状不写现场：会话 id、机器路径、日期与轮次、带单位的读数、具体对象名、结论、进度、修订史这八类都不许留在共享文档里；保存前跑一遍检测行（十六位十六进制、`/Users/`、`http`、日期、带单位的读数、`total=`、`pending=`），命中就是实例，改写为“怎么取到它”或移到项目临时区；检测结果要贴一行 `detection: clean` 或命中清单，没记录等于没跑。例子里的名字也是实例，要写成 `<an instance>` 这种形状。换一个项目再读一遍：一句话在换项目、换领域、换处境后不成立，就说明它带着实例状态；按角色命名而不是按所有者命名。
把当前工作区的顶层目录名当禁词：保存前逐个 `grep -c`，命中就换成角色名（设计文档、长报告、文献清单）；共享文档里出现项目名，等于告诉下一个 agent 在读别人的文件，而这个名字离开这台机器就没有意义。只用文档里已经有的词：写作时临时造的标签、比喻、缩写，要么首次出现时一句话定义，要么换成文档原本的说法。


### 3.3 感官可复核

是让判断可被感官复核：第一句给结果，观察要描述构成（哪个对象、站在哪、哪个数来自哪一行），把专有名词换成 X 后句子仍然说得通，命令放在它支撑的判断之后。机械步骤不许替代判断：数关键词叫阅读、正则回复叫判断、`grep` 字段叫核对、同名就算同物，都不算。只有当对象本身没有可把握的意义时（校验和、行数、哈希）才保留机械步骤。判“是否理解”“是否合理”的判据要么改写成可指的对象，要么删掉。密度以“读者能行动”为准：交代处境、阅读顺序、收口的闸门，用平实的句子；碎片清单让人猜下一步是太薄，同一件事换三种说法重述是太厚。

### 3.4 契约式交接

是契约式交接：写清交了什么、什么算没交（当场退回，不隔一轮，不猜“大概忘了”）、接收方怎么一眼判（一条可跑命令，或一句能点头的话）。不许给契约套自造编号、评分表、关键词匹配或“多写一点保险”。边界画在交接那一刻，不画在语法上：同一个 `grep -c` 守着交接边缘时是契约，替代阅读时是机械。

### 3.5 规则挂在动作上

是让规则挂在动作上：每节开头一行写它存在的目的；先给动作，再给失败的样子；写触发时刻（“改动之前”“跑回来时”“交接时”）而不是写话题；一条一款一个动词，需要两个动词就是两条；写给下一个 agent，用祈使句，不写状态、不写实例、不讲这一轮的故事。
按流程或按分类切节，不按补丁切：标题的顺序就是事情发生的顺序，或主题的分类，一级一类；出现 `四之二`、`1.1b`、“补充之二”这类补丁号，说明结构没规划过——把补丁并回它所属的节并重编号；只有一句话的节并进邻节。只读标题列表：读不出这份文档做什么、按什么顺序做，就先重组再写下一行。
检查挂在它守的那一步上，不单独成章：一块对应流程里的一步、或主题的一类。“检查”章只有在检查本身就是某个人在固定时刻做的一步时才成立，否则每条命令回到它守的那一步——标题的检查挂在标题规则下，节数差的命令放进“先比”那一步。判断法：删掉这一章，若某一步因此少了验证方法，它就是一步；若什么也没少，它就是伪装成规则的目录。


### 3.6 按流程切分，不按类别切分

读者是按“下一步做什么”来用文档的，所以一节就是一步，节的顺序就是动作的顺序。

1. 一节一步。读完一节，末句把它交给下一节。
2. 验收属于被验收的那一步。判某步是否做完的命令写在那一步末尾，不单列“检查”一章——单列会让读者同时抓两个地方。
3. 触发条件也不是一章。“什么时候必须做”是那一步的条件；单列成一节，读起来像第二条流程。
4. 不许有账本式章节。靠追加事例、例外、轶事长大的章节已经不是流程，它想教的规矩应当写成需要它的那一步里的一句话。
5. 每条编号以动词开头，且那个动词是一个命令。“读两侧”而不是“读两侧的重要性”；读者要能不解释就执行这一行。判据：`grep -cE '^[0-9]+\. (读|数|比|判|改|跑|写|删|记)'` 与 `grep -cE '^[0-9]+\. '` 两个数必须相等，否则那条编号只是披着编号的散文。
6. 节数是读数不是评价。`grep -c '^## '` 前后各数一次：加了标题却没加步骤，就是多加了一个迷路的地方。
