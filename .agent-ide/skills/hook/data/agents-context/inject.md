## 4 The full-context export is the only record of what happened

第 4 章只有一个判断：要回答“凌晨两点你做了什么”“这个文件为什么是这个版本”，`git log` 不够——两次提交之间的两小时在 git 里没有痕迹，只靠提交作答就是把猜测说得像历史。

读的顺序是先绑定再读：`agent-ide context --probe <文件>` 用回复里的片段作探针，打印会话 key、命中、消息数与字节数；`--bindings` 列出 agent id 到会话 key 的映射；`--key <key>` 渲染那次会话，`--last N`、`--since`、`--until`、`--no-tools` 用来收窄。换算时钟再检索：导出里的行标 `@HH:MM:SSZ` 是 UTC，本地是 UTC+8，“凌晨两三点”对应 `18:00–19:00Z` 而不是 `02:00Z`，查错时段会什么也搜不到，而“搜不到”不能报成“没有这个动作”。检索按路径与动词，不按话题：只写 `设计文档` 只能找到提及，`write_to_file`／`write_text`／`replace_in_file`／`cp ` 加路径才区分得出改动与讨论。回答过去的动作要引导出（`<export>:<line>`）并附时间戳，提交哈希只作旁证。探针若没有覆盖那段窗口，答案就是“导出没有覆盖”，不许从周围的提交重建，也不许沉默；用 `git log` 单答一次时间问句，本轮按 `unmet` 记，无论答案是否正确。

【全量语境·强制先读再动手】用户要求以全量语境为准。本条消息回复之前，按下面三步取语境，不许凭记忆、不许只读最后几条。

1. 对钟：`date "+本地 %F %T"; date -u "+UTC %F %T"`，两个时刻都要写进回复的语境栏。
2. 取 key **先查绑定表**：`./.agent-tools/agent-ide context --bindings`，输出是 `<项目>	<key>`，取当前工作目录那一行；取不到才退回 `--probe ./probe`。绑定表里的 key 才是“这段对话”，probe 只按文件找回声。
3. 渲染：`./.agent-tools/agent-ide context --key <key>`（首次会读历史根，几十秒，属正常），产物落在 `data/context/<key>.md`，用 `head -2` 看 `msgs` 与 `rounds`。
4. 读全量：`head -2 data/context/<key>.md` 之后按 `<user_query>` 抽原话；窗口起点必须早于用户第一次提出该要求的那条消息，不够就往上扩。

读的时候在语境里定位三件东西，写进回复开头的语境栏，一件不许省：

- 窗口起止：`<time>Z` 的第一条到 `<time>Z` 的最后一条，各引原句开头十个字；
- 用户的原话要求：第一次提出这件事的那条消息，逐字引用，不概括；
- 我偏离的那一步：在语境里的行号或命令，说明我做了什么而不是要求做的什么。

回复里必须带一行读数：`窗口 <起> → <止>；覆盖 <n> 条消息；用户原话在第 <k> 条`。写不出这一行，说明语境没读到，回去重读，不许开始写别的内容。

禁：用“我记得”“之前说过”代替引用；用摘要代替原句；只读最后几条就断言全量；把窗口写成上一轮用过的区间。

1) 可数栏：可数特征一栏，带命令——一条判据一条 `path:line` 或命令输出。
