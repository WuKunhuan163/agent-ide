# Closed-loop status answers template (asked at any moment)

**The shape is fixed**; being "only a quick question" is no reason to degrade it into a status report. Four answers, two lists, four states.

## 1. The four questions (each paragraph a path plus a reading, no adjectives)

1. **what gets built**: `<path>` + one reading (recomputable with `ls` / `grep`)
2. **what the manuscript reads like**: how this stretch reads, and **which neighbour it is compared against**
3. **what each section owes**: `<section>` — owes `<what>` — owned by `<who>`
4. **what is being done now**: how many on-ramp items, how many in-loop, the order, **which in-loop items wait until on-ramp closes**

## 2. The open-items list (one item per line)

`<item> — stuck on <what> — owes <who> — next action <one sentence>`

## 3. Next round's item table

`who | which file | paves: | acceptance line (with a number) | release`

## 4. The four states (what it looks like once the loop closes)

1. every clause lands on `carried: <path:line>` or `excluded: <part> — <reason>` (neither = not closed)
2. **the paving site**: the reserved section name or the column to be filled, and which section it goes in
3. which reading lines `## EXIT-READINGS` will hold
4. the `## EXCLUDED` list and next round's starting point

**Three prohibitions**: ① writing a "progress is good" narrative; ② changing the convention because someone asked (the owner did not change his words, so the convention stands); ③ giving only "next-step suggestions".
