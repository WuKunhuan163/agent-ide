# Hugging Face Tool

## Install

When `.agent-tools/huggingface` is missing, install it from the skill directory:

```bash
python3 .agent-ide/skills/agent-ide/agent-ide.py install --project . huggingface
```

The launcher is generated by `agent-ide`; it runs `huggingface.py`.

## What it does not do

One streaming GET per file (`requests`, `timeout=60`): no retry, no resume, no certificate fallback; if the response `Content-Length` disagrees with the bytes received, it exits non-zero. One file per call — no repo walking, no sharding.

## Output contract

stdout carries the result only, one line, tab-separated:

| Command | stdout |
|---|---|
| `download` | `<absolute path>\t<bytes>` |
| `config` | `<path to config.json>` |
| `get` | `<token>` |

Progress, sizes, HTTP status and failures all go to stderr with an `[hf]` prefix. Progress is drawn only when stderr is a TTY, so piped values stay clean:

```bash
path=$( .agent-tools/huggingface --id <id> download --repo gpt2 --file config.json -d ./ckpt | cut -f1 )
```

Exit codes: `0` success; `1` HTTP error / network error / byte-count mismatch / no token / missing `--id`.

## Credentials

Isolated per agent id; the token lands in that id's own config directory:

```bash
.agent-tools/huggingface --id <id> config --token <token>
.agent-tools/huggingface --id <id> get
```

Path: `.agent-ide/skills/huggingface/data/accounts/<id>/config.json`.

## Download

**Download takes the file, not the model name, and the block below is the call that returns a path**: a name that resolves to nothing fails here rather than at training.

```bash
.agent-tools/huggingface --id <id> download --repo <repo_id> --file <filename in repo> [--revision main] -d <output dir>
```

```bash
# a small public file
.agent-tools/huggingface --id <id> download --repo gpt2 --file config.json -d /tmp/

# a large weight file
.agent-tools/huggingface --id <id> download --repo <repo_id> --file <file.safetensors> -d ./checkpoints/
```
