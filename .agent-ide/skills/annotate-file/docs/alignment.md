# 口径对齐：介绍文档与本体文档的同步契约

分册用途：当一份介绍文档（`*-intro.md`、`thesis-idea-intro.md` 一类）被打开、被批注、被回填时，介绍与本体两边怎么写、怎么同步、谁说了算，以这一篇为准。SKILL.md 讲命令，这一篇讲口径。

六块，按做一份介绍的顺序排：原则、首行、内容、同步、绑定、注意事项。前五块是动作与判据，第六块是不做的事。

## 一、原则

1. **默认对齐。** 介绍里的每一条信息，除非用户明确要求删改，都必须与本体同口径——同一组数字、同一套术语、同一个编号、同一处限定语。介绍里出现的数字，本体里必须有；本体里改了数字，介绍当轮跟着改。
2. **特殊要求叠加在默认之上，不是替换。** 用户说“只介绍第 3–5 章”，做法是只写第 3–5 章，其余章节的默认对齐义务暂停——范围由“哪些节存在”表达，不靠一句话声明。用户说“挂文献注脚”，做法是两侧都在同一句后挂同一条注，键取自 `references.bib`，不得一侧有注、另一侧无注。
3. **介绍不承担主张。** 介绍里不出现本体没有的判断、不出现“更好”“更清晰”这类评价；介绍只描述本体写了什么、按什么顺序写、每节各自的落点在哪。
4. **两个方向都回流。** 介绍与本体是一份文本的两种形态：本体的改动回到介绍，批注在介绍上形成的结论也回到本体。只往一个方向改，另一侧就是旧版，读者读到哪一版取决于他先打开哪个文件。

## 二、首行与标题

1. **第一行只有一种写法**：

   ```
   # <文件名> 口径对齐介绍文档
   ```

   `<文件名>` 是被介绍的那份本体的文件名，含扩展名，例如 `# 立意.md 口径对齐介绍文档`、`# 长文.md 口径对齐介绍文档`。落笔前先跑 `head -1 <介绍>`，输出必须与这行一致。

2. **第一行之后直接进正文**：一个空行，接着就是本体的第一节（或其 `###` 小节）。范围限定用“只写范围内的节”表达：范围内没有的节不出现，读者从缺少的节名看出范围。

## 三、内容与语体

1. **语体跟着本体走，不默认学术语体。** 先判本体是哪一类，再取语体：论文与报告用陈述句、第三人称，术语逐字一致，不写“我们做了什么”“接下来我会”；技能文档、规范、守则用指令型语体——祈使句、一条一个动词、写触发时刻与失败的样子，不写“本技能旨在……”；代码与配置按符号说事，函数名、字段名、默认值逐字照抄，讲清谁读它、读的顺序、改哪里会坏；项目树与目录结构按状态说事，一层一句，先给这一层有几项再给哪项是什么；列表、表格、词表按条目说事，先给列与顺序，再逐条交代口径来源。这五类只是常见几种，用来对照，不是清单也不是上限：本体不属于其中任何一类时，读它自己的语体重写，判据是同一类读者读完不必切换读法。
2. **成段写，分条必编号。** 每一节先用一段自然语言交代“这一节写了什么、为什么排在这里、它把读者交给谁”；一旦把动作或条目分开写，每条前面必须有编号——`1.`／`2.`／`3.`，次级用 `a.`／`b.`／`c.`，或条数本身承担编号的 `一、二、三`。出现“照此执行三条：甲，乙，丙”这类无编号的并列句，按未编号计：读者数不清有几条，少了哪条也看不见。分条最多到第二层，超过两层说明该拆节。
3. **首句给结论。** 每段第一句是这一段要说的事，第二句起给依据（数字、节号、本体里的原句），末句交代与下一段的接缝。
4. **引用与注脚两侧同形。** 用户要求挂注时，介绍的注与本体同键、同位置语义；键必须在项目根下的 `references.bib` 里存在，缺键先补键再挂注。
5. **不出现本体没有的数。** 介绍里的任何数字都要能在本体里指到一行；指不到的数不写，或写成“本体此处未给数”。

## 四、同步

**同步是什么**：同步是把介绍与本体改到同口径的那串动作——读两侧、比差异、判谁新、把另一侧改到与之一致，并且允许方向相反：批注在介绍上定了结论，就把那结论送回本体。一次同步结束的标志是两侧同口径、读数留证。

**serve 不属于同步**：`annotate-file open` 只建立或刷新页面实例（提交一次、重置 baseline、清掉 diff 底色），它既不比较两侧，也不决定谁说了算。把 serve 当成同步的一步，会让人以为“页面还能打开”就等于两侧已经对齐。

**什么时候必须同步**（命中任一条就做，不命中就不做）：

1. 本体新增或删除一节之后。
2. 本体里任何数字、术语、引用键改动之后。
3. 介绍上收到批注并形成结论之后。
4. 用户提出范围限定（“只介绍 3–5 章”）或体例要求（“挂注脚”“用学术语体”）之后。
5. 交付前最后一次读回，作为 `1.9` 检查的一项。

**怎么做**，五步，不跳步：

1. **先比。** 逐节比对四样：节数与节名、术语、数字、引用键。两条命令直接给数：`grep -c "^## " <介绍>` 与 `grep -c "^## " <本体>` 的差必须为 0（范围限定时按限定范围计）；`diff <(grep -o "\[\@[^]]*\]" <介绍> | sort -u) <(grep -o "\[\@[^]]*\]" <本体> | sort -u)` 必须为空。差异一行一处写进当轮读数（`<临时区>/<本轮>/readings.md`）。
2. **判定谁新。** 以较新编辑的一方为准——判据是那一节的实际内容与最近一次提交，不是文件的整体 `mtime`。两侧各自改了不同的节时逐节取新，不做整篇覆盖。
3. **改到同口径。** 改一侧，当轮把另一侧改到同一口径，不手抄节选、不整篇覆盖。
4. **改一处，两侧同改。** 当轮把发现的不同步两侧改完，不允许“先改介绍，本体下一轮再说”。
5. **留证。** 读数写三行：比出几处差异、以哪一侧为准、同步后两侧各多少行。

## 五、绑定：默认份份对应

默认情况下，一份本体只配一份介绍、一个实例 id，幂等使用：改介绍就在原文件上改，`--id` 不变。出现第二份介绍时，两份都还在被读，读者无法判断哪一份是当前口径——这与 `3.1-8` 禁止的“同一目的建第二个文件”是同一件事。

绑定可以变，条件是用户明确要求整份重做（“重新介绍”“整份重写一版”）：这时换新文件或新 id 是允许的，旧绑定的处置要一句话说明（并入后删除，或留在原处不再引用）。换绑之后，新绑定从建立那一刻起同样幂等——不因为“刚重做过”就可以随手再建第三份。

## 六、注意事项

1. **不写 overview。** overview 指正文之前交代“这篇覆盖什么、一共几节几行、什么时候写的、下面按什么顺序讲”的那段概述，含覆盖范围、章数、行数、版本、日期与“下面逐节介绍”这类过渡句；它是关于介绍的说明，不是本体内容，且不会随本体变化。落笔前用 `sed -n '3p' <介绍> | grep -c "覆盖\|章、"` 读数，必须为 0。
2. **不整篇重写。** 用户点了哪一节就改哪一节；整篇重写会把没要求改的句子一起换掉，术语、限定语、注脚都会跟着漂。改动落到点名之外就还原；某一段改不动时，指出是哪一段并停手。
3. **不重新 serve。** 页面读磁盘文件，改完刷新即见；只在用户说 serve、打开、重新打开、给我看这一版时执行 `open`。
4. **不另起第二份介绍。** 见第五块：默认一份，换绑需用户点名，换绑后仍幂等。
5. **不列禁止写法。** 把错误形态逐条列出来，等于把错误写法示范一遍；只写正确写法，错的自然无处可落。
6. **不自造词。** 标签、比喻、缩写，要么首次出现时一句话定义，要么换成文档已有的说法。
